# 昆山产业学院教学辅助网页

课堂用的**班级 + 加分**管理网页：每个班一份名单、一套独立的加分记录，随机点名只是班级工作台里的一个快捷入口。

**纯前端、零依赖安装、离线可用**——双击 `index.html` 就能跑。


---

## 快速开始

1. 双击打开 `rollcall/index.html`（Chrome / Edge 均可，推荐全屏 F11）。
2. 首页点 **导入名单**，把 `sample/学生名单示例.xlsx` 拖进窗口，或点 **选择文件**。
3. 预览页选好「导入到哪个班级」→ **确认导入**。示例表格带「班级」列，选「按班级列自动拆分」会一次建出 5 个班。
4. 点某个班级卡片进入**班级工作台**：左边是加分面板，右边是学生名单 + 随机点名按钮。

没有现成表格时，首页直接 **＋ 新建班级**，再进班级里手动录入。

## 信息架构

```
首页（顶栏：全校概览 + 操作）
 ├─ 标签页「🏆 排行榜」（默认）
 │    ├─ 本周之星：前三领奖台 + 4–15 名列表（本周榜 / 总榜 / 自定义期限）
 │    └─ 班级总分排名：前三领奖台 + 其余班级（周 / 月 / 总排名 / 自定义期限）
 ├─ 标签页「所有班级」→ 班级卡片网格
 │    └─ 点班级卡片 → 班级工作台
 │         ├─ 左（宽）：学生名单舞台
 │         │    ├─ 每张卡片左下累计总分、右下当天得分
 │         │    ├─ 点卡片 → 右侧「当前学生」直接显示分数（不弹窗）
 │         │    └─ 随机点名按钮（空格）→ 抽中后可直接 +1 或跳去加分
 │         └─ 右（窄）：加分栏
 │              ├─ 当前学生：姓名 + 总分 + 今日得分、加入选中 / 清空记录
 │              ├─ 加分对象：勾选模式 / 全选 / 清空（未使用时自动收起）
 │              ├─ 加分操作：−1 −2 +1 +2 +3 +5，自定义分 + 必选原因
 │              └─ 本班加分记录：逐条删除、导出本班分数表（Excel）
 └─ 点「🎮 小游戏」→ 课堂小游戏页（26 个玩法，Esc 或 ← 返回来处）
```

**加分是主角，点名是入口**：点名的结果条上直接给了「+1」和「给 TA 加分」，抽完就能记分。

## 界面一览

界面全部是纯 CSS 手写，没有引入任何 UI 框架。主要几屏：

- **登录页**：深蓝品牌区 + 反白 LUXSHARE 字标，底部铺低透明度校园线稿剪影；账号密码 / 教务一键 / 访客三种登录方式并列，下方「记住账号密码」默认勾上。
- **首页**：顶栏一行全校概览（班级数 / 学生数 / 累计分）+ logo，下面两个标签页——
  - **排行榜**：本周之星（前三领奖台，冠亚季各站一只立可牛，尺寸按名次递减）+ 4–15 名列表；班级总分排名 + 班级平均分排名，都支持周 / 月 / 总 / 自定义期限。
  - **所有班级**：正方形班级卡片网格，每张卡显示人数 / 总分 / 平均分与本班前三（放大字号 + 相对榜首比例条）。
- **班级工作台**：左侧宽名单舞台（卡片左下累计分、右下当天分，点卡片直接在右侧显示，不弹窗），右侧窄加分栏（当前学生 / 加分对象 / 加分操作 / 本班加分记录）。随机点名按钮在名单标题右侧，抽中后结果条上有 `+1` 和「给 TA 加分」。
- **课堂小游戏**：26 个玩法按场景分档，卡片式入口。
- **人员管理 / 设置 / 导入预览 / 导出**：均为弹窗，样式与主界面同一套。

## 班级

| 操作 | 位置 |
| --- | --- |
| 新建 | 首页右上 **＋ 新建班级** |
| 重命名 | 班级卡片 hover → ✎ |
| 删除 | 班级卡片 hover → ✕（连带该班名单与加分记录） |

## 导入名单

- 支持 **xlsx / xls / csv**，拖到页面任意位置也行（拖动时全屏提示「松开鼠标导入名单」）。
- **自动识别表头**：找「姓名 / 名字 / 学生 / name」列、「学号 / 编号 / id」列、「班级 / 分组 / 组别」列；表头不在第一行也能找到。
- 无表头时**兜底取第一列**当姓名。
- 导入前有**预览**：显示共几人、识别到了哪些列、工作表名、会拆成几个班，可**逐条删除**不想要的行。
- 重复行自动去重。
- **手动录入**：一行一个，支持 `姓名,学号,班级`、`姓名 学号`、纯姓名。

### 归属班级怎么选

预览页有一个「导入到哪个班级」下拉：

| 选项 | 行为 |
| --- | --- |
| **按「班级」列自动拆分**（默认） | 表格里有班级列就按列拆成多个班，一次建好 |
| **未分班** | 全部归到「未分班」这个虚拟班级 |
| **归到「X」** | 整份名单塞进已有的某个班 |
| **新建班级…** | 输入新班名，整份名单归到它 |

**班级名默认取文件名**：导入 xlsx / csv 时，预览页会自动把「新建班级…」的输入框填成表格文件名去掉扩展名后的结果（例如 `电气2301.xlsx` → `电气2301`），并自动切到「新建班级…」。这个名称**可以随手改**，改完点「确认导入」即可。表格里本身带「班级」列且拆出多个班时，仍然按列自动拆分，不会被文件名覆盖。

**导入是增量合并**：只替换被导入到的那些班的名单，**其他班级原样保留**。所以可以分多次把不同班的名单导进来。

## 加分

### 三种加分方式

1. **点卡片给单人加**（主流程）：点名单里任意卡片 → 右侧「当前学生」显示姓名、总分、今日得分 → **先选原因** → 再点 `−2` `−1` `+1` `+2` `+3` `+5` 或填自定义分。**不弹窗，不打断点名。**
2. **勾选后批量加**：开「勾选模式」→ 点卡片多选（或「全选」）→ 选原因 → 点分数按钮。一次给多人各加同样的分。有「当前学生」时，分数按钮只加给该生；关掉「当前学生」（点「取消」）后才作用于勾选集合。
3. **点名后加**：抽中学生的结果条上有 `+1` 和「给 TA 加分」两个按钮。**`+1` 的原因固定写「答疑加分」**，不用再选，点一下就落账。

自定义分支持小数（`step="0.5"`），可填负数扣分。

**加分栏的操作顺序是「先原因、后分值」**：下拉框在最上面，分数按钮在它下面。这样一进来就先看到「这次为什么加分」，不会出现「先点了 +1、发现没选原因」的来回。原因没选时，6 个分数按钮会一起压暗（`opacity .5`）提示还没到那一步，提交按钮也是灰的。

**加分原因必选**：右侧加分栏里是一个下拉框，五选一——

| 选项 | 说明 |
| --- | --- |
| 1 · 答疑加分 | 也是点名结果条 `+1` 的默认原因 |
| 2 · 作业加分 | |
| 3 · 课堂表现 | |
| 4 · 问题扣分 | 配合负分使用 |
| 5 · 其他 | 选中后旁边会多出一个「补充说明」输入框，**必填**，最多 40 字 |

没选原因时「给当前学生加分 / 给选中学生加分」按钮是灰的，点不动；选了「其他」但没填补充说明，按钮仍然是灰的。原因会一起存进记录和 CSV。

**每条记录都记操作人**：提交按钮上方有一行 `操作人：深之一`，落账时把当前登录者的**真名**（`displayName`，没有就退回登录名）写进记录的 `op` 字段，记录列表每行右侧显示操作人姓名，旧数据没有操作人的显示 `—`。导出加分流水 CSV 时第 8 列也是操作人。这样讲师和管理员加的分能分清是谁加的。

### 记录与统计

- 每条记录：分值、原因、**操作人姓名**、时间、所属学生。
- 学生卡片**左下角是「总分」**（蓝色，格式「总分 8」）、**右下角是「今日得分」**（绿色，格式「今日得分 3」；当天没加分显示灰色「今日得分 0」；扣分为红色）。两种分数颜色不同、字号跟着卡片放大，卡片上不再显示学号。
- 面板顶部是**班级总分**，底部是**本班加分记录**（倒序，逐条可删）。
- 底部控制条：已抽 / 剩余 / 总数。
- 顶部摘要条：**班级总分** + **本班前三名**（①②③ 徽章，显示姓名与分数）。
- 首页顶栏中间是**全校概览**（班级数 / 学生数 / 累计分），不再显示学生姓名。
- 首页每张班级卡片：**人数**、**总分** 两格 + **本班前三名**（姓名与分数，没加分显示「还没有加分」）。卡片是正方形，班名与前三名完整显示、不截断，管理按钮挪到卡片右下角悬停显形，不会盖住班名。

### 撤销（多步）

工具栏的 **↶** 按钮（或 `Ctrl+Z` / `⌘Z`）可以逐步撤回加分操作，最多回退 40 步：

| 会被记录进撤销栈的操作 | 说明 |
| --- | --- |
| 加 / 扣分 | 批量加分、单人加分、点名结果条加分 |
| 删除一条加分记录 | 面板列表里点 ✕ |
| 清空某个学生的记录 | 右侧加分栏「当前学生」的「清空记录」 |

- **撤销栈按班级隔离**：切到别的班，撤销按钮会自动置灰（那个班没有可撤的操作）。
- 按钮置灰时鼠标悬停会提示「没有可撤销的操作」，可用时提示「还可撤销 N 步」。
- 撤销后班级总分、前三名、学生卡片徽标、面板记录列表、首页统计会一起回滚。
- 撤销栈只在内存里，**刷新页面后清空**（加分数据本身不会丢，只是不能再往前撤）。

### 班级隔离

**每个班级的加分记录完全独立**，存在各自独立的 localStorage 键里（`rollcall.scores.v1.<班级名>`）。切换班级时名单、总分、记录列表全部同步刷新，互不干扰。

## 导出

### 学生分数表（Excel）

| 入口 | 导出内容 |
| --- | --- |
| 工作台顶部「⤓ 导出本班分数表」 | 本班全体学生 → 一个 `.xlsx` |
| 面板底部「导出本班分数表」→ 弹窗逐个点 | 指定班级 → 一个 `.xlsx` |
| 首页「导出全部班级分数表」/ 弹窗「全部导出」 | 所有班级 → 一个 `.xlsx`，**每班一个 sheet** |

**一行一个学生，没加过分的学生也在表里**（加分次数与总分都写 0）。列固定 6 个：`序号,姓名,学号,班级,加分次数,总分`。

- 表头**冻结**（滚动时首行不动）+ **细边框**，纸张 A4 纵向、宽度自适应一页，打印出来可以直接发给家长。
- 文件名按「班级名 + 日期」：`电气2301_学生分数表_2026-11-21.xlsx`；全部导出时叫 `全部班级_学生分数表_2026-11-21.xlsx`。
- 生成器是自己写的最小 XLSX（`js/xlsx-writer.js`，STORE 模式 zip + 手写 sheet XML）。**没有用 vendor 里的 SheetJS 写**，因为社区版写文件不支持冻结窗格和边框样式（只能读）。

### 加分流水（CSV）

| 入口 | 导出内容 |
| --- | --- |
| 排行榜「⤓ 导出」 | 当前板块的当前周期（学生榜 TOP15 或班级榜），文件名带总榜/周榜/月榜/自定义区间 |

文件名带班级和日期：`一班_加分记录_2026-11-20.csv`。带 BOM + CRLF，Excel 直接双击打开不乱码。

列：`序号,班级,姓名,学号,分值,该生累计,原因,操作人,时间`

> 工具栏那个 ⤓ 按钮导出的是**点名抽取记录**（谁被抽到过），和加分记录是两套数据。

## 排行榜

首页顶部两个标签页切换：**🏆 排行榜**（默认）和 **所有班级**。排行榜是独立界面，不是弹窗，整块占满一行宽度，直接排在所有班级卡片上方。

页面分两个板块，各自带周期切换与导出：

| 板块 | 内容 |
| --- | --- |
| **本周之星**（学生榜） | 前三名领奖台（🥇 冠军居中最高）+ 第 4–15 名列表；标题随周期变成「本周之星」/「总分之星」 |
| **班级总分排名** | 前三名领奖台 + 其余班级列表；**所有班级**都上榜，一条记录都没有的班显示「暂无数据」（不是 0），有记录但正负抵消成 0 的班如实显示 `0` |

| 周期 | 范围 |
| --- | --- |
| **本周榜 / 周排名** | 本周一 00:00 起（学生榜默认） |
| **月排名** | 本月 1 日 00:00 起（仅班级榜） |
| **总榜 / 总排名** | 全部历史记录（班级榜默认） |
| **自定义** | 自己填起止日期，两端都可留空（留空 = 该端不限） |

周期按每条加分记录的时间戳过滤，不重置任何数据——同一批记录可以随时切周期看不同口径。班级榜周期选完会被记住，下次打开还是那个周期。

### 自定义期限

点板块右上角的 **自定义** 会出现一行日期栏：两个日期框 + 「近 7 天」/「近 30 天」/「清除」三个快捷按钮。

- 两个日期都含端点（结束日按当天 23:59:59 算），只填一端也能用（例如只填开始日 = 从那天起到现在）。
- 起止填反了会自动换回来，不会出现空榜单。
- 榜单标题与说明会跟着变：学生榜变成「限定期之星」，说明写 `11-15~11-21 · 8 名学生上榜`。
- **导出跟着期限走**：导出的 CSV 只含该期限内的记录，文件名带区间，例如 `学生总分261115-261121TOP15_2026-11-21.csv`、`班级总分261101-261121_2026-11-21.csv`。
- 自定义期限、当前周期都记进 `rollcall.state.v1`，刷新后原样恢复。


**领奖台只放真正有分数的班级**：0 分班不占领奖台（否则「暂无数据」看起来像荣誉），而是从第 3 名开始往下排；不足 3 个时补一个占位，保证冠军始终居中。

## 随机点名

班级工作台右侧的 **随机点名** 按钮（或按 `空格` / `回车`）。三种动画：

| 动画 | 效果 | 适合 |
| --- | --- | --- |
| **聚光灯**（默认） | 全班名字铺成卡片网格，高亮框快速跳动 → 减速 → 定格命中卡片放大发光，其余卡片虚化 | 人数少、想让全班看到所有人 |
| **滚屏** | 老虎机式上下滚动名字，easeOutExpo 减速停住 | 氛围最紧张，大屏效果最好 |
| **幸运转盘** | Canvas 扇形转盘 + 顶部指针 + 抽中彩带粒子 | 抽奖感最强 |

顶部胶囊按钮或键盘 `1` `2` `3` 切换。

命中后结果条上有 `+1` 和「给 TA 加分」，抽完直接记分。

### 公平性保证

**结果在动画开始前就已经用 `crypto.getRandomValues` 抽定，动画只是表现层**——先定人，再算转盘要转多少度、滚屏要滚多少行，保证动画停在哪就是谁。不存在"看着是 A 停住却显示 B"的情况。

抽取算法：Fisher-Yates 洗牌取首位的等价实现（`js/picker.js`），`randInt` 用拒绝采样消除取模偏差，实测两万次分布均匀。

### 抽取规则

- 默认 **本轮不重复**：抽过的人不再出现，抽完提示「本轮已抽完，按 R 或点 ↺ 重置」。
- 可选 **可重复模式**（底部开关）：每次都从全体里抽。
- 不永久移出名单，重置即恢复。**抽取状态按班级独立**，切班不会串。

## 课堂小游戏

首页顶栏和班级工作台顶栏都有 **🎮 小游戏** 按钮。进去是 26 个即拿即用的热场玩法，全部为纯前端实现、离线可用，投到教室大屏就能开。

**导航是一层，不是新窗口**：从首页进就回首页，从班级进就回班级（`state.gamesFrom` 记住来处）；`Esc` 或左上角 `←` 返回。玩法和面板都嵌在同一套导航里，风格与主应用一致（白蓝主题、同一套按钮与卡片）。

### 玩法分三档

| 徽标 | 含义 | 网页里能做什么 |
| --- | --- | --- |
| **可互动** | 有完整网页实现 | 点按钮就能玩，屏幕负责出题、计时、计分、揭晓 |
| **辅助工具** | 网页只做辅助 | 提供计时器 / 画板 / 记录板，主体仍在教室里进行 |
| **规则卡** | 依赖真实身体动作 | 网页只投影一张大字规则卡，照着做即可 |

### 26 个玩法

| 分类 | 玩法 |
| --- | --- |
| 🔥 热身局 | 击鼓传花、逢 7 过、**数字炸弹**、两真一假、**少数派** |
| 🧠 脑力局 | 成语接龙、姓名接龙、绕口令大挑战、单词大比拼、热座 |

### 三个为课堂大屏新增的原创玩法

设计原则：**屏幕只负责放大和裁决，人负责输入**。大屏课堂可用的输入只有四种——举手、起立走动、齐声喊、拍桌，所以新玩法全部围绕这四种设计。

- **少数派**（热身局）：屏幕给三个选项（可现场改文字），全班同时举手，老师数人头点 `+1`，揭晓时高亮**人数最少**的那个选项，请他们说说理由。关键在「同时举手」——分开举会互相看，答案就趋同了。
- **站队**（身体局）：二选一，学生起立走到教室左半边或右半边，**必须选一边、不能站中间**。天平随人数倾斜，揭晓时显示两边百分比。只显示比例不显示绝对人数，小班不尴尬。
- **三句话**（观察局）：抽一位同学说三句关于自己的话（每句 ≤10 字），其中一句是假的，全班投票。**投票期间隐藏票数**，揭晓才一次性公布——否则后面的人会跟着前面投票，游戏就废了。

### 数字炸弹为什么改成「只报冷热」

原版给的是「大了 / 小了」的精确提示。1–100 的范围里，这等于把二分法直接教给学生：7 次就能锁定，50 人的班只有 7 个人参与，剩下 43 个当观众。

改成五档模糊反馈后二分法失效，必须集体推理：

| 档位 | 触发条件（与炸弹的距离 / 范围） | 提示 |
| --- | --- | --- |
| 🔥 烫 | ≤ 3% | 就差一点点了！手别抖。 |
| 🌶️ 热 | ≤ 9% | 非常接近了，再收一收。 |
| 🌤️ 温 | ≤ 18% | 有点感觉了，继续逼近。 |
| 🌥️ 凉 | ≤ 34% | 还在外围，方向得再想想。 |
| ❄️ 冰 | 其余 | 离得很远，重新估算一下。 |

配套还有两件事：**音调随温度升高而变尖**（880 / 720 / 600 / 480 / 360 Hz，不看屏幕也能听出接近程度）；**分组接力**（默认 6 组，每次猜测自动切下一组，6 组班能让每组都轮到）。

### 移植与隔离方式

小游戏代码来自独立项目 `课堂破冰游戏`，移植时做了三层隔离：

1. `js/games/games-data.js` — 26 个玩法的元数据（分类、档位、规则、物料、提示）。
2. `js/games/renderers.js` — 16 个互动玩法的渲染器，通过 `window.RENDERERS.gNN(stage, api)` 注册。
3. `css/games.css` — 由 `tools/scope-games-css.mjs` 从旧项目样式表机械转换而来，**每条规则都带 `#screenGames` 前缀**，所以不会污染主应用样式。

`js/games/games-app.js` 是胶水层：渲染卡片网格与分类筛选、开关面板（`.sheet`）、桥接 `window.toast` / `window.tone` / `window.burst` 三个旧项目依赖的全局函数。**这三个必须在 `renderers.js` 之前挂上**，脚本顺序是 `games-data → games-app → renderers → voice`。

## 数据源：本地模式与远程模式（P1）

同一份前端有两种数据源，由 `js/data/adapter-factory.js` 自动判定，**不需要两个版本**：

| 打开方式 | 模式 | 数据在哪 | 说明 |
| --- | --- | --- | --- |
| 双击 `index.html`（`file://`） | 本地 | 本机浏览器 localStorage | 完全离线，不发任何请求 |
| 服务器访问（`http(s)://`）且 `/api/v1/healthz` 可用 | 远程 | 服务端数据库 | 登录、权限、多端同步 |
| 服务器访问但后端不可用 | 本地（回退） | 本机浏览器 localStorage | 底部黄条提示，课堂不中断 |

强制切换：URL 加 `?mode=local`（或 `?offline=1`）走本地，加 `?mode=remote`（或 `?remote=1`）走远程，用于排查问题。

**为什么读接口是同步的**：`app.js` 2454 行、49 个存储调用点全部同步；远程模式下数据先进内存缓存，UI 立刻拿到，写操作同步更新缓存 + 异步补传。这样切数据源不用把整个前端改成 async，课堂交互零延迟。

**远程模式的离线队列**：写操作先落内存缓存与本地副本，同时把请求塞进 `rollcall.queue.v1` 队列（带 `Idempotency-Key`）。网络恢复、页面重新可见、启动 0.8s 后都会自动补传；服务端靠幂等键去重，不会重复加分。4xx 视为数据本身有问题直接丢弃并记录，5xx 与网络错误保留重试。

## 账号与权限（P1）

每次打开都要登录。**本机模式同样有登录**——账号和会话都存在这台电脑的浏览器里；服务器模式的账号在服务端数据库里，换电脑登录看到的是同一份数据。

系统内置一个最高管理员，首次启动自动创建，**没有「首次使用」注册面板**：

| 项目 | 值 |
| --- | --- |
| 账号 | `wjqcool` |
| 姓名 | 深之一 |
| 密码 | 部署文档约定的初始密码 |
| 角色 | 管理员（最高） |

密码**只以哈希形式存在**：服务端是 scrypt（`rollcall/server/src/auth/seed.ts` 里的 `DEFAULT_ADMIN_PASSWORD_HASH`），本机模式是 PBKDF2（`rollcall/js/auth/auth-store.js` 里的 `DEFAULT_ADMIN.pw`）。明文既不写进前端代码，也不写进仓库和启动日志。校验脚本：`node rollcall/tools/verify-admin-hash.mjs`。

登录后请到「账号 → 修改密码」换成自己的密码。`seed` 只在账号不存在时创建，改过的密码不会被重启重置；`ensureDefaultAdmin()` 同样只补缺、不覆盖。

### 三种登录方式

登录页顶部三个按钮并列，点哪个就展开哪种方式：

| 方式 | 说明 |
| --- | --- |
| **账号密码** | 用上面那个管理员账号，或管理员在「人员管理」里建的账号登录 |
| **教务一键登录** | 走教务系统 SSO。P3 阶段才真正接入，现在点会提示「尚未配置」，可先用账号密码 |
| **访客登录** | 一键进纯只读模式，不用账号密码，适合教室大屏 / 公开课 |

访客登录在本机模式下自动补一个内置 `guest` 账号（`role='viewer'`，密码是随机哈希所以永远登不上密码登录）；服务器模式下走 `POST /api/v1/auth/guest`，服务端建/取同一个内置 `guest`（`password_hash = NULL`，同样登不了密码）。两种模式都不会创建任意新账号。

### 记住账号密码

账号密码表单下方有个「记住账号密码」勾选框，**默认勾上**。勾着的时候：

- 登录成功后把账号密码存进 `localStorage` 的 `rollcall.login.remember.v1`，下次打开登录页自动回填，直接点「登录」就能进。
- 退出登录后回填保留（下一节课换个人讲，改掉账号即可，不用重新敲一遍）。
- 取消勾选立刻清掉已存内容；再勾上会把当前输入框里的值存下来。

两个边界处理：

- **只在登录成功后才写**。密码输错不会把错的密码记下来。
- **密码失效时只留账号**：如果自动填充的密码已经不对了（比如在别处改过密码），登录失败时会把存着的密码清空，只保留账号。否则每次打开都自动撞一次错误密码。

存储形式是 base64，**这不是加密，只是避免明文直读**。本项目是纯前端课堂工具，密码本来就在本机 `localStorage` 里做哈希校验；如果将来接真实教务账号，这里必须改成「只记账号、不记密码」。

### 三种角色

| 角色 | 能做什么 | 典型场景 |
| --- | --- | --- |
| **管理员** | 全部功能，含人员管理、权限分配、清空数据 | 教务处 / 电教老师 |
| **讲师** | **所有班级都能看**（名单、总分、加分记录）；加减分、撤销、删除记录**只在自己任教的班级**可用，其他班级只读 | 任课老师 |
| **访客** | **纯只读**：只能看班级列表、总分、前三名、排行榜（含名单）。**不能点名、不能点开学生、不能进班级工作台、不能导出、不能做任何修改** | 教室大屏 / 公开课 |

另有 **本机用户**（本地模式下未建账号时的兜底角色），权限等同管理员。

### 讲师：看得见全部，改得动自己那几班

讲师的班级列表**不做过滤**，6 个班全在首页；但只有任教班级能改：

- 非任教班级卡片带灰色「只读」角标，卡片右上角的「重命名 / 导入 / 删除」三个按钮**不渲染**。
- 进非任教班级的工作台，顶部出琥珀色提示条「只读班级 · 可以查看名单、总分与加分记录，但加减分与撤销只在你的任教班级可用」，左侧加分面板整体置灰并加「只读」角标。
- 即使绕过界面（改 DOM 或直接调 API），`addScore` / `undoStep` / 删除记录 / 清空学生记录都会在入口被拦下并提示「「XX」不在你的任教范围内，只能查看」。

实现上把授权拆成两层：`viewScopes()` 决定**能看哪些班**（讲师默认 `class.view_all` 打开 → 全部），`classScopes()` 只决定**能改哪些班**（只看管理员勾选的任教班级）。单一 scope 表达不了「全看得见、只改自己那几班」。

### 权限怎么生效

- **两层校验**：权限决定「能不能做这个动作」（如 `score.add`），任教班级范围决定「对哪些班能做」。两层都过才放行。
- **管理员不走权限表**，恒全开——否则管理员一误操作就能把自己锁死。
- **讲师 = 角色默认值 ⊕ 管理员逐项覆盖**，覆盖只存与默认值不同的项，权限表升级后新增项自动继承默认。
- **管理员专属权限不可授予**（如 `user.manage`、`data.migrate`），界面上直接锁住。
- 没有权限的按钮分两种处理：`.perm-off` 置灰不可点，`.perm-hide` 直接隐藏（如「导出全校」对讲师就是隐藏而非置灰）。

### 安全边界（重要）

前端的 `can()` **只决定界面显示与否，不是安全边界**——懂技术的人改 localStorage 就能绕过。真正的强制校验在服务端（P1 第 4 项已完成会话与权限基础，业务接口在 P2）。当前前端这层的作用是「防误操作 + 减少误触」。

密码用 PBKDF2 派生后存储，不存明文。局域网 `http://` 属于非安全上下文，浏览器不提供 `crypto.subtle`，所以内置了纯 JS 的 SHA-256 + PBKDF2 兜底路径，按记录里的 `algo` 字段自动选路，旧哈希始终可验证。

### 人员管理

管理员点右上角头像 → **人员管理**，可以新增账号、改角色、勾选任教班级、逐项调整权限、停用或删除。编辑已有账号时登录名锁定不可改（避免历史记录对不上人）。

**至少保留一个启用的管理员**——把最后一个管理员降级或停用会被拒绝。

**两种模式行为一致**：本机模式下账号存在浏览器 `localStorage`（`rollcall.users.v1`），服务器模式下存在服务端 `app_user` 表。界面层只认一个统一入口 `js/auth/user-store.js`，它在 `RCSession.isRemote()` 为真时转发到 `/api/v1/users*`，否则调本地的 `RCAuthStore`；密码由调用方始终以明文传入，本机模式在浏览器里 PBKDF2 派生后存哈希，服务器模式直接发给服务端由 scrypt 派生，两边都不落明文。

服务器模式比本机模式多几条硬约束（因为是多用户共享一个库）：

- 改角色 / 改权限 / 改班级范围 / 停用 / 重置密码 → **吊销该账号全部会话**，旧标签页立刻失效，不能拿着旧权限继续跑。
- 内置最高管理员 `wjqcool` 可以改资料、改密码，但**不能降级、停用或删除**（`seed.ts` 每次启动会补建它，允许删除就会变成「重启后又冒出一个密码未知的管理员」）。
- 任何字段变更都写 `audit_log`，`before` / `after` 各留一份。

### 技术选择与理由

| 选择 | 理由 |
| --- | --- |
| `node:http` + 自写 89 行 Router，不用 express | 只有 20 来条路由，私有化部署时依赖越少越好 |
| 驱动可切换（`DB_DRIVER=sqlite\|pg`） | 本机没 PostgreSQL 也能一键跑；生产切 PG 只改一个环境变量 |
| 迁移单份 SQL + 方言占位符 | 维护两套 DDL 必然漂移，一套加替换层能保证两边结构一致 |
| 密码用 Node 内置 scrypt | 原生 argon2/bcrypt 装不上；scrypt 同为内存硬 KDF，OWASP 认可 |
| 库里只存 session token 的 sha256 | 库泄露也拿不到可用 token |

### 接口一览

**基座**：`/healthz`、`/readyz`（同时支持根路径与 `/api/v1` 前缀）、`POST /api/v1/auth/login`、`POST /api/v1/auth/logout`、`POST /api/v1/auth/guest`、`POST /api/v1/auth/refresh`、`POST /api/v1/auth/password`、`GET /api/v1/me`。

**P4 人员管理**（6 条路由，均要求 `user.manage` 权限）：

| 接口 | 说明 |
| --- | --- |
| `GET /api/v1/users` | 账号列表，字段对齐 `auth-store.js` 的 `safe()` |
| `POST /api/v1/users` | 新增账号，登录名查重、工号查重，默认强制首次改密 |
| `PATCH /api/v1/users/:id` | 改资料 / 角色 / 权限 / 班级范围 / 停用启用 |
| `POST /api/v1/users/:id/password` | 管理员重置他人密码，不需要原密码 |
| `DELETE /api/v1/users/:id` | 删除账号 |
| `GET /api/v1/users/meta` | 角色与权限项定义，供前端渲染勾选表 |

**P2 领域**（21 条路由）：

| 接口 | 说明 |
| --- | --- |
| `GET/PUT /api/v1/classes` | 班级列表与当前班级 |
| `GET/PUT /api/v1/roster` | 名单，body 是数组本身 |
| `GET/PUT /api/v1/settings` | 界面设置 |
| `GET/PUT/DELETE /api/v1/classes/:name/scores` | 本班加分记录 |
| `GET /api/v1/classes/:name/scores/all` | 含已冲正行的完整明细 |
| `GET /api/v1/leaderboard?period=all\|week\|month` | 班级榜 + 学生榜 |
| `GET /api/v1/edu/status`、`POST /api/v1/edu/sync` | 教务对接状态与一键同步 |

响应统一带 `X-Request-Id`；错误体 `{code, message, details}`；写请求要求 `X-CSRF-Token`（双提交，`rc_csrf` cookie 非 HttpOnly 供前端读）；会话空闲 30 分钟、绝对 12 小时，单用户并发上限 5。

**加分写入是「对账」语义**：前端把本班全部记录当真相 `PUT` 上来，服务端逐条比对——已存在且值未变则跳过，值变了则冲正旧行再插新行，不存在则新增。所以重复发送同一批记录不会重复加分，断网重放安全。

### 教务名单一键读取

服务端配好 `EDU_BASE_URL` 与 `EDU_TOKEN` 后，首页顶栏会出现「🔄 读取教务名单」按钮：

```bash
EDU_BASE_URL=http://教务服务器地址 EDU_TOKEN=访问令牌 node src/index.ts
```

同步规则：

- **学生**按「学号 → 身份证摘要 → 同班同名」三步匹配，匹配上就更新，匹配不上就新建。
- **学生被移出名单后教务又读回来，会复活原记录而不是新建一条**：移出是软删（保留行给加分流水留引用），读回时把 `deleted_at` 清空，加分历史始终挂在同一个 `student_id` 上。同步结果里 `revivedStudents` 会报告复活数量。
- **身份证只存 sha256 摘要**，库里不落明文（计划书 §12 明确不采集身份证号）。
- **教师**按工号匹配，已存在的账号只补姓名与工号，**绝不覆盖密码和权限**——你在系统里调过的权限不会被同步冲掉。
- **任教班级用并集合并**，一个老师教两个班时第二次同步会追加而不是覆盖。
- 教务里已消失的班级**不删除**，只停止更新，避免误删历史加分记录。

本地 mock 联调（不需要真实教务系统）：

```bash
node scripts/mock-edu.mjs 3400
EDU_BASE_URL=http://127.0.0.1:3400 EDU_TOKEN=demo-token node src/index.ts
```

未配置 `EDU_BASE_URL` 时按钮置灰、弹窗显示「未配置教务系统地址」；本机模式（`file://`）下按钮带 `is-off` 类并提示需用服务器模式打开。

## 适配

- **16:9 大屏优先**，1366×768 到 1920×1080 都实测铺满无滚动条。
- 尺寸用 `vmin` + `clamp()` 缩放，窗口大小变化自动重排。
- 卡片网格列数不是写死的：`anim-spotlight.js` 的 `fitGrid()` 按人数和容器尺寸枚举所有列数，用「卡片比例 + 空格子数 + 填充率」打分选最优，所以 4 人不会拉成 4 条长条，60 人也不会挤成一团。
- 字号跟随卡片尺寸，人少时字大，投影后排也看得清。长名字不会截断：`fitNames()` 会按卡片宽度自动缩字号兜底。
- 首页班级卡片是**正方形**，网格 `minmax(clamp(268px, 21vw, 372px), 1fr)`，1264 宽排 4 列、1920 宽排 4 列且更大；班名与「本班前三」都完整显示，管理按钮在卡片右下角悬停才出现。
- 结果条高度是**实测**后写进 CSS 变量 `--result-reserve` 的，所以弹出前后卡片不会跳动。
- 尊重 `prefers-reduced-motion`，系统开了减少动效会自动降级。

## 常见问题

**数据存在哪？会上传吗？**
只存在你自己浏览器的 localStorage 里（键名前缀 `rollcall.`），不上传任何服务器。班级列表和抽取状态各一个键，每个班的加分记录各一个键。换电脑或换浏览器要重新导入。设置里「清空本机数据」可一键清除。

**删除班级会删掉加分记录吗？**
会，一起删。删除前有确认框。

**重命名班级会丢数据吗？**
不会。学生归属和加分记录会一起迁到新班级名下。

**导入会不会覆盖其他班？**
不会。只替换被导入到的那些班的名单，其他班级原样保留。

**能放服务器上吗？**
能，纯静态文件，扔任何静态服务器都行。不过本地双击 `file://` 打开就能用，没必要。

**想换成自己的班级名单？**
直接把你的 Excel 拖进去，识别到姓名列就能用。列名不必完全一致，「学生姓名」「名字」都能认出来。

**抽完一轮怎么重来？**
点底部 ↺ 或按 `R`。抽取记录不会清，只有本轮池子重置。
